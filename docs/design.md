# 族谱系统设计方案（v0.4）

> v0.4 更新：纳入全部扩展功能（第 10 节），AI 功能仅预留接口暂不实现；重排分期。
> v0.3 更新：明确"超级管理员 → 家族管理员"两级管理。
> v0.2 更新：根据确认的决策定稿——多家族平台、按推荐技术栈、国内云部署、仅管理员录入、女儿后代有数据即入谱、新增"任意两人亲属关系"。

## 0. 已确认决策

| 项目 | 决策 |
|---|---|
| 平台形态 | **多家族平台**（SaaS），一个系统托管多个族谱，数据按家族隔离 |
| 技术栈 | Vue 3 + uni-app（Web 与小程序共享代码）+ NestJS + PostgreSQL |
| 部署 | **国内云**（腾讯云/阿里云），需 ICP 备案域名 + HTTPS |
| 编辑权限 | **仅管理员录入/修改**，族人只读，无审核流 |
| 管理层级 | **两级**：平台超级管理员为每个家族指定家族管理员；家族管理员只能管理自己的家族 |
| 纸质谱导入 | 暂不做；预留"标准导入格式（Excel 模板）"，后期拍照 → OCR/人工整理 → 导入 |
| 女儿后代 | **有数据即可入谱**，系统不限制只记父系 |
| 新增能力 | **任意点选两人，显示辈分差与亲属称谓** |

## 1. 目标

- Web 网页 + 微信小程序双端登录查看，共用后端与账号。
- 支持数百年、数十代、单族上万人。
- 核心可视化：**五代树**（上五代祖先 + 下五代后代）与 **亲属关系查询**。
- 档案：姓名、字、号、昵称、性别、世代、字辈、排行、祖籍、生卒、生平、照片、视频、音频。

## 2. 角色与权限（两级管理）

```
平台超级管理员（最高权限）
 ├─ 家族A：家族管理员 ── 族人（只读）
 ├─ 家族B：家族管理员 ── 族人（只读）
 └─ 家族C：家族管理员 ── 族人（只读）
```

| 角色 | 范围 | 权限 |
|---|---|---|
| 平台超级管理员 | 全平台 | 创建/停用家族；**为每个家族任命、更换、撤销家族管理员**；查看全平台操作日志；可代管任意家族 |
| 家族管理员 | 仅本族 | 录入/编辑本族成员、关系、多媒体、族谱信息；邀请/移除族人；**看不到也改不了其他家族** |
| 族人 | 本族 | 只读，可看在世成员的敏感信息 |
| 访客 | 公开族谱 | 只看姓名与世系，隐藏在世者隐私 |

- 每个家族默认一名家族管理员；数据结构上允许多名（如需副管理员），由超级管理员决定。
- 任命方式：超级管理员在"家族管理"页输入用户手机号 → 设为该族管理员；对方用该手机号登录即获得权限。
- 所有接口按 `clan_id` 做数据隔离与权限校验；超级管理员的任免操作写入审计日志。
- 一个用户可属于多个家族（如在 A 族是管理员、在 B 族是族人）；家族可设为公开 / 私密 / 邀请制。
- 登录：手机号验证码 / 密码（Web）、微信登录（小程序），同一手机号可绑定合并账号。

## 4. 数据模型

```
Clan        id, name, surname, hall_name(堂号), origin(郡望), generation_poem(字辈诗),
            founder_id, visibility(public/private/invite)
User        id, phone, email, password_hash, wechat_openid, wechat_unionid, is_super_admin
Membership  user_id, clan_id, role(admin/member), linked_person_id
Person      id, clan_id, surname, given_name, courtesy_name(字), art_name(号), nickname,
            gender, generation(世代, 始祖=1), generation_char(字辈), rank_in_siblings(排行),
            birth_date, birth_precision(年/月/日/约), birth_text(原文，如"康熙三十年"),
            death_date, death_precision, death_text, is_living,
            ancestral_home(祖籍), birth_place, burial_place,
            biography(富文本), occupation, is_external(外姓配偶), privacy_level
ParentChild parent_id, child_id, relation_type(亲生/过继/出继/收养/兼祧), is_main_line, sort_order
Marriage    id, husband_id, wife_id, type(元配/继配/侧室), order, start/end
Media       id, person_id, type(photo/video/audio/doc), storage_key, thumbnail, duration, caption
Event       id, person_id, date, date_text, place, type(迁徙/科举/任职/…), description
AuditLog    id, clan_id, user_id, entity, entity_id, action, before, after, at
```

要点：
- **模糊日期**：日期 + 精度 + 原文，支持朝代年号与农历。
- **女儿后代**：亲子关系不区分父系/母系，女儿的子女直接挂在女儿名下；树和关系计算都支持。
- **过继/兼祧**：一人可有多组父母，`is_main_line` 标记宗法主线；五代树默认走主线，可切换看生父线。

## 5. 五代树

- 中心人物居中，上方 5 层祖先（父 → 祖 → 曾祖 → 高祖 → 天祖），下方 5 层后代（子 → 孙 → 曾孙 → 玄孙 → 来孙）。
- 配偶并列显示，男女不同配色，已故/在世标识，显示字辈与世代。
- 交互：缩放、拖拽、点击节点换中心、悬停简介、按层折叠、导出图片。
- 接口：`GET /persons/:id/tree?up=5&down=5`，PostgreSQL `WITH RECURSIVE` 一次取子图；后代过多时按层懒加载。
- 渲染：Web 用 AntV G6；小程序用 Canvas 2D（F6 / ECharts tree）。

## 6. 亲属关系查询（新增）

**交互**：在树上依次点选两人（或搜索选择）→ 弹出结果卡片：
- 称谓（双向）：如"张三 是 李四 的 **堂叔**；李四 是 张三 的 **堂侄**"
- 辈分差：如"相差 1 代（张三长一辈）"；同族时显示双方世代与字辈
- 关系路径：在树上高亮 A → 共同祖先 → B 的连线，并列出文字链"父亲的哥哥的儿子"

**算法**：
1. 在 父母–子女–配偶 关系图上找最短路径（优先经血缘，其次经婚姻）；血亲以 **最近共同祖先（LCA）** 求出双方到祖先的代数 m、n。
2. 辈分差 = 世代号之差（同族）或 m − n。
3. 把路径转成称谓链文本（爸爸的哥哥的儿子），交给开源库 **relationship.js**（mumuy/relationship，MIT 协议）得出标准称谓，覆盖父系、母系、堂/表、姻亲。
4. 库覆盖不到的远房族亲（超过五服）：按规则生成"族兄 / 族叔祖 / 族侄孙"等，并附"同出第 N 世祖 XXX，相差 K 代"。
5. 路径上的兄弟长幼依据排行/出生日期，决定"伯/叔""兄/弟"。

**接口**：`GET /kinship?from=A&to=B` → `{ termAtoB, termBtoA, generationDiff, commonAncestor, path[], chainText }`

## 7. 技术架构

```
 Web (Vue3 + Element Plus + G6) ─┐
                                 ├─► Nginx ─► NestJS API ─┬─ PostgreSQL（主数据、递归查询）
 微信小程序 (uni-app) ────────────┘                         ├─ Redis（缓存、验证码、会话）
                                                           └─ 腾讯云 COS / 阿里云 OSS + CDN（照片/音视频）
```

- 仓库结构（monorepo）：`apps/api`（NestJS）、`apps/web`（Vue3）、`apps/miniapp`（uni-app，三期）、`packages/shared`（类型、API 客户端、亲属计算）。
- 部署：Docker Compose，国内云服务器；域名 ICP 备案；小程序建议企业/个体户主体注册。

## 8. 隐私与安全

- 在世者的生日、电话、住址仅族人可见；访客只看姓名与世系。
- 多媒体使用签名 URL、防盗链；数据库每日备份，可导出冷备份。
- 管理员所有修改写入操作日志。
